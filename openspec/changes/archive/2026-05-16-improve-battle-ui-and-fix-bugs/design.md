## Context

当前战斗页面使用左右分栏布局：左侧为手牌区+悬浮按钮，右侧为战斗日志。英雄/怪兽状态面板为纯文字罗列属性。顶部状态栏包含关卡、回合、Boss 状态、怪兽元素提示。

布局问题：
- 属性面板信息密度低，纯文本横向排列
- 操作按钮悬浮在卡牌下方空白区
- 顶部状态栏信息过多

同时存在两个 bug：
1. 眩晕状态下英雄不能出牌，若手牌全是攻击卡则无卡可出，回合无法推进（死锁）
2. 怪兽技能的 `elementImmune`（元素免疫）没有在 `battle-calculator.ts` 的伤害管线中应用

## Goals / Non-Goals

**Goals:**
- 按静态页面预览 (`layout-preview.html`) 实现全新战斗页面布局
- 修复眩晕状态下的回合推进死锁
- 修复元素免疫技能在伤害计算中生效

**Non-Goals:**
- 不改动核心战斗逻辑（出牌、伤害计算的基本公式不变）
- 不新增卡牌类型或战斗机制
- 不改变存档系统

## Decisions

### 决策 1: 布局组件拆分方式
**方案**：在现有组件基础上改造，不创建新组件。
- `StatusBar.vue` — 居中，只保留关卡和回合
- `HeroStatus.vue` — 属性 2×2 网格，居中标题
- `MonsterStatus.vue` — 属性 2×2 网格，居中标题，技能标签化，元素信息整合到网格
- `BattleView.vue` — 整体布局重构，新增底部操作条容器

**理由**：现有组件结构清晰，复用现有组件比新建更易维护。

### 决策 2: 眩晕死锁修复方案
**方案**：在 `game-engine.ts` 的 `monsterCounterAttack()` 中，如果英雄眩晕且下一回合开始时手牌没有可用卡（全是攻击卡），自动推进回合并丢弃/替换手牌，或添加一个"跳过回合"按钮。

**更好的方案**：眩晕时英雄仍然可以出牌（因为眩晕只影响被攻击时的判定，不影响主动出牌），所以真正的问题可能在于——眩晕时玩家**以为**不能出牌而放弃操作。

**重新分析**：需要查看 `CardHand.vue` 和 `playCardAction` 是否对眩晕做了禁用判断。如果眩晕导致所有卡牌 disabled，且没有跳过回合的机制，则死锁。

**最终方案**：
1. 眩晕时不禁用卡牌（保持可点击），但眩晕效果只影响"被攻击时的判定"（如眩晕技能）
2. 或者：眩晕时禁用卡牌，但提供一个"跳过回合"按钮在操作栏中

### 决策 3: 元素免疫技能修复
**方案**：在 `battle-calculator.ts` 的伤害管线中，在元素倍率计算步骤检查攻击方的元素是否等于免疫方的 `immuneElement`，如果相等则倍率为 1.0（不受克制/被克影响）。

**理由**：这是伤害计算管线中最自然的插入点，不影响其他计算步骤。

## Risks / Trade-offs

- **布局重构风险**：BattleView.vue 改动较大，需要确保响应式数据绑定不丢失。通过保持现有 computed/ref 名称来降低风险。
- **眩晕修复**：需要确认眩晕的语义——是"不能行动"还是"被攻击时判定"。需要根据游戏设计意图选择方案。
- **元素免疫**：需要确认免疫是"完全不受该元素影响"还是"该元素克制/被克关系无效"。当前理解为后者。
